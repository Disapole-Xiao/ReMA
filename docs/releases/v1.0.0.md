# ReMA v1.0.0 — Concurrent Jobs and Remote Worker Restart

ReMA now supports concurrent command execution and remote worker restart through shared storage.

**Highlights**

- Run multiple jobs on one worker. `busy` no longer blocks submissions; each job has its own Bash process group, log, and exit code.
- Restart an online worker with `rema restart <name>`, preserving its working directory. By default, running jobs finish first; `-f` terminates the worker’s tracked jobs before restarting.
- Use `rema jobs <name>` to list running jobs, or add `-a` / `--all` to include queued tasks and history.
- Stop one job with `rema kill <name> <job_id>`. A job ID is now required.
- `rema stop <name>` waits for running jobs to finish; `stop -f` terminates them.

**Upgrading Steps**

Stop submitting new jobs until these steps are complete. Existing jobs can continue running.

1. **Update the client.** On the machine where you normally type `rema` commands, open your ReMA repository and switch to this release:

   ```bash
   cd /path/to/ReMA
   git fetch origin --tags
   git checkout v1.0.0
   rema --version
   ```

   Replace `/path/to/ReMA` with the directory you originally cloned. The version output should be `rema 1.0.0`. An existing symlink installation does not need reinstalling.

2. **Restart each online worker.** Run these commands from the same client machine:

   ```bash
   rema list
   rema restart gpu-server
   ```

   Replace `gpu-server` with a worker name shown by `rema list`. Repeat for each online worker.

   Restart waits for running jobs to finish, then starts the updated worker in its original working directory. Wait for the `restarted` message before continuing. You do not need to log in to the target machine.

3. **Verify that commands work.**

   ```bash
   rema run gpu-server -- 'echo upgrade-ok'
   ```

   You should see `upgrade-ok` and an exit code of `0`. You can now resume submitting jobs.

If you also use the ReMA CLI from another machine with a separate repository checkout, repeat step 1 there. Remote restart updates the worker; it does not update that machine’s separate CLI installation.
