# ReMA v1.1.0 — Multi-Worker Commands and Record Retention

ReMA can now inspect jobs across workers, remove workers that have remained offline, and automatically erase expired job records.

**Highlights**

- `rema jobs` lists running jobs on every registered worker. Add `-a` or `--all` to include queued and completed jobs. Supply multiple worker names or quoted glob patterns to narrow the list.
- `rema rm` removes all eligible offline workers. It also accepts multiple names or quoted glob patterns. A worker must have been offline for at least one day by default; set `REMA_RM_OFF_DAYS` to change the interval. Use `REMA_RM_OFF_DAYS=0 rema rm <name>` to remove an offline worker immediately.
- Completed job records and output disappear after seven days by default. Set `REMA_LOG_KEEP_DAYS` to change the interval. Expired records are not available through `jobs` or `log`.
- The default offline detection threshold is now 180 seconds, with retries for temporary shared-storage read failures. The worker cleans old records in the background so cleanup does not delay heartbeats.

**Upgrading Steps**

1. **Update the client.** On the machine where you normally run `rema`, open the existing ReMA checkout and switch to this release:

   ```bash
   cd /path/to/ReMA
   git fetch origin --tags
   git checkout v1.1.0
   rema --version
   ```

   The version should be `rema 1.1.0`. An installation linked to this checkout does not need reinstalling. Repeat this step on any other machine with a separate checkout used as a client.

2. **Restart each online worker after its active jobs finish.** From the updated client, list workers and restart each online worker:

   ```bash
   rema list
   rema restart server-name
   ```

   Replace `server-name` with a name from `rema list`. The restart loads the updated worker code in its original working directory; it does not reboot the machine. Do not use `-f` if its running jobs should finish normally. Offline workers will load the new code when they are started again from an updated checkout.

3. **Verify the upgrade.** Choose an online worker and run:

   ```bash
   rema run server-name -- 'echo upgrade-ok'
   rema jobs
   ```

   The command should print `upgrade-ok`, exit with code 0, and leave no running job in `rema jobs` after it finishes.

`rema rm` now waits one full day before removing an offline worker unless `REMA_RM_OFF_DAYS` is changed. Plan manual removal accordingly.
